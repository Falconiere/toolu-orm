# Composite primary key and AUTOINCREMENT

**Feature:** `#[primary_key(a, b)]` on a `#[table]` declares a composite key stored as
`TableDef.primary_key` and rendered as a trailing `PRIMARY KEY ("a", "b")`.
`#[column(primary_key, autoincrement)]` on an `Integer` column renders
`PRIMARY KEY AUTOINCREMENT` on SQLite and `GENERATED BY DEFAULT AS IDENTITY`
on Postgres. Mixing table-level and column-level primary keys is a compile
error. A key-set change diffs as table recreation on SQLite.
**Drivers:** SQLite (real libsql) for DDL execution; both dialects for SQL
generation.
**Spec:** issue #65.

## What is proven

| Shape | Proof |
|---|---|
| Composite `PRIMARY KEY (memory_id, tag)` | Generated SQL runs on libsql; duplicate `(memory_id, tag)` inserts fail; a second tag for the same memory succeeds |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | Generated SQL runs on libsql; two `DEFAULT VALUES` inserts get ids `1` then `2` |
| Macro / DDL / diff | `#[primary_key(...)]` and `autoincrement` land in `TableDef`; key-set and autoincrement flips emit SQLite recreation SQL; trybuild pins the mixed-key and autoincrement compile errors |

## How to run

```sh
cargo nextest run -p toolu-orm-cli --features libsql -E 'binary(composite_pk_sqlite_test)'
cargo nextest run -p toolu-orm-core -E 'binary(sql_test) + binary(diff_test)'
cargo nextest run -p toolu-orm-macros --features postgres -E 'binary(table_macro_test)'
cargo nextest run -p toolu-orm-macros -E 'binary(compile_fail_test)'
```
