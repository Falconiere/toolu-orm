# LanceDB DDL, constraints, and search SQL

**Scope:** Issue #157 probes the isolated Rust `duckdb =1.10505.0` binding with bundled DuckDB `v1.5.5` and signed Lance extension build `2f167ea`. The probe runs against fresh local Lance directories on macOS 26.6.2 arm64; the same pinned suite runs on Ubuntu 24.04 x86_64 in CI. Run `bash scripts/check-lancedb-smoke.sh` to verify the extension checksum and execute the real-data cases.

The SQL below is the SQL sent by the tests. `'<items-uri>'` and `'<search-uri>'` stand for the quoted absolute paths of `items.lance` and `search_items.lance` inside that run's disposable directory; only that unpredictable directory prefix changes. `lance_probe` is the attached namespace. Results were read after closing DuckDB and reopening the same Lance directory where stated. Errors are stable leading messages; the full runtime text includes a temporary path, source location, and/or SQL caret.

## Observed SQL matrix

| Capability | Actual SQL (URI substituted as above) | Observed result on pinned Rust backend | Later public policy |
|---|---|---|---|
| Create and populate | `CREATE TABLE lance_probe.main.items (id BIGINT, label VARCHAR, vec FLOAT[2])`; `INSERT INTO lance_probe.main.items VALUES (1, 'one', [0.0, 0.0]), (2, 'two', [1.0, 0.0])` | Succeeds; rows remain after reopen. | Permit this supported declaration subset only after its owning adapter issue validates it. |
| Add, rename, drop column | `ALTER TABLE lance_probe.main.items ADD COLUMN score BIGINT DEFAULT 7`; `ALTER TABLE lance_probe.main.items RENAME COLUMN label TO title`; `ALTER TABLE lance_probe.main.items DROP COLUMN score` | All succeed on populated data. `DESCRIBE lance_probe.main.items` after reopen returns `id, title, vec`. | Permit only separately verified safe schema steps; no blanket ALTER claim. |
| Scalar type change | `ALTER TABLE lance_probe.main.items ALTER COLUMN id TYPE DOUBLE` | Fails: `Cannot cast column "id" from Int64 to Float64`; old `id` survives reopen. | Refuse this change before mutation. |
| Vector dimension change | `ALTER TABLE lance_probe.main.items ALTER COLUMN vec TYPE FLOAT[3]` | Fails: `Cannot cast column "vec"` from a fixed-size list of length 2 to 3; `vec` remains after reopen. | Refuse dimension changes before mutation. |
| Drop table | `CREATE TABLE lance_probe.main.drop_case (id BIGINT)`; `DROP TABLE lance_probe.main.drop_case` | Both succeed; selecting `drop_case` after reopen gives `Table with name drop_case does not exist`. | Permit only the verified drop form when migration support is added. |
| Scalar index and uniqueness counterexample | `CREATE INDEX id_idx ON '<items-uri>' (id) USING BTREE`; `SHOW INDEXES ON '<items-uri>'`; `INSERT INTO lance_probe.main.items VALUES (1, 'duplicate', [2.0, 0.0])`; `SELECT count(*) FROM lance_probe.main.items WHERE id = 1` | Index `id_idx` appears after reopen. Duplicate insert succeeds; the count returns **2**. | BTREE may be a non-unique scalar index. Refuse any unique guarantee. |
| Drop scalar index | `DROP INDEX id_idx ON '<items-uri>'`; `SHOW INDEXES ON '<items-uri>'` | Succeeds; index list is empty. | Permit the verified path form when index migration support is added. |
| PK, UNIQUE, NOT NULL, CHECK declarations | `CREATE TABLE lance_probe.main.pk_case (id BIGINT PRIMARY KEY)`; `CREATE TABLE lance_probe.main.unique_case (id BIGINT UNIQUE)`; `CREATE TABLE lance_probe.main.not_null_case (id BIGINT NOT NULL)`; `CREATE TABLE lance_probe.main.check_case (id BIGINT CHECK (id > 0))` | Each fails: `Not implemented Error: Lance CREATE TABLE does not support constraints`; no dataset is created. | Refuse all four guarantees before table mutation. |
| FK declaration | `CREATE TABLE lance_probe.main.fk_case (id BIGINT REFERENCES lance_probe.main.items(id))`; `USE lance_probe`; `CREATE TABLE fk_within_case (id BIGINT REFERENCES items(id))` | Qualified reference fails: `FOREIGN KEY constraints cannot be defined cross-database`. Inside the Lance namespace, it fails: `Failed to create foreign key: there is no primary key or unique constraint for referenced table "items"`. | Refuse FK guarantees before mutation. |
| Unique index syntax | `CREATE UNIQUE INDEX unique_idx ON '<items-uri>' (id) USING BTREE` | Fails at `USING` with `Parser Error: syntax error at or near "USING"`; ordinary BTREE already accepts duplicates. | Refuse unique-index requests; this syntax is not evidence of an alternative guarantee. |
| DML rollback and commit | `BEGIN; INSERT INTO lance_probe.main.tx_items VALUES (2); ROLLBACK; BEGIN; INSERT INTO lance_probe.main.tx_items VALUES (3); COMMIT;` | After reopen, seed ID 1 and committed ID 3 exist; rolled-back ID 2 does not. | Record this narrow DML observation; do not promise general multi-statement transaction support. |
| DDL in transaction | `BEGIN; INSERT INTO lance_probe.main.tx_items VALUES (4)`; `ALTER TABLE lance_probe.main.tx_items ADD COLUMN added BIGINT`; `ROLLBACK` | ALTER fails: `Not implemented Error: Lance DDL does not support explicit transactions yet`; after reopen ID 4 and column `added` are absent. | Refuse a DDL transaction before mutation. |
| Vector L2 top-k | `SELECT id, _distance FROM lance_vector_search('<search-uri>', 'vec', [0.0, 0.0]::FLOAT[2], k = 2, use_index = false) ORDER BY _distance` | Seed vectors `[0,0]`, `[1,0]`, `[2,0]` return `(1,0.0), (2,1.0)`. No ANN index is used. | This fixed-dimension L2 subset is a candidate for later portable search. |
| Vector dimension mismatch | `SELECT id, _distance FROM lance_vector_search('<search-uri>', 'vec', [0.0, 0.0, 0.0]::FLOAT[3], k = 2, use_index = false)` | Fails: `query dim(3) doesn't match the column vec vector dim(2)`. | Refuse mismatched dimensions before query execution. |
| Vector filtering | `SELECT id, _distance FROM lance_vector_search('lance_probe.main.search_items', 'vec', [0.0, 0.0]::FLOAT[2], k = 2, use_index = false, filter = 'tag = ''keep''', prefilter = true) ORDER BY _distance`; `SELECT id, _distance FROM lance_vector_search('<search-uri>', 'vec', [0.0, 0.0]::FLOAT[2], k = 2, use_index = false, filter = 'tag = ''keep''', prefilter = true)`; `SELECT id, _distance FROM lance_vector_search('<search-uri>', 'vec', [0.0, 0.0]::FLOAT[2], k = 2, use_index = false) WHERE tag = 'keep' ORDER BY _distance` | Namespace prefilter returns IDs 2 and 3 with distances 1 and 4. Raw-path `filter` fails: `Invalid Input Error: lance_vector_search filter parameter is only supported for namespace-backed tables`. Outer `WHERE` *after* raw-path top-k returns only ID 2. | Use a verified namespace prefilter where available; refuse raw-path filter and do not treat outer `WHERE` as equivalent. |
| Unindexed and indexed FTS | `SELECT id, _score FROM lance_fts('<search-uri>', 'body', 'fox', k = 2) ORDER BY _score DESC`; `CREATE INDEX body_idx ON '<search-uri>' (body) USING INVERTED`; `SHOW INDEXES ON '<search-uri>'` | Unindexed search returns IDs 1 and 2 with positive scores. After index creation and reopen, `SHOW INDEXES` lists `body_idx`; search still returns IDs 1 and 2 with positive scores. This proves persistence and result behavior, not an index-use or speed guarantee. | Keep index use/performance claims out of the common contract. |
| FTS filtering | `SELECT id, _score FROM lance_fts('lance_probe.main.search_items', 'body', 'fox', k = 2, filter = 'tag = ''keep''', prefilter = true) ORDER BY _score DESC`; `SELECT id, _score FROM lance_fts('<search-uri>', 'body', 'fox', k = 2, filter = 'tag = ''keep''', prefilter = true)` | Namespace prefilter returns ID 2 with positive score. Raw-path `filter` fails: `Invalid Input Error: lance_fts filter parameter is only supported for namespace-backed tables`. | Require the verified namespace prefilter form; refuse raw-path filter. |

These are observed bounds of this pinned pair and these inputs. In particular, a successful `CREATE INDEX` says nothing about uniqueness, and a successful `BEGIN` says nothing about DDL atomicity. The refusal column is guidance for later adapter and capability issues; this PR does not add a public refusal API.
