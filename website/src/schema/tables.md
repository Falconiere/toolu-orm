# Defining tables

`#[table]` takes a struct of marker types and produces the schema metadata, the
typed columns, and the builder factories for that table.

```rust
use toolu_orm_core::column::{Integer, Text, Uuid};
use toolu_orm_core::table::TableSchema;
use toolu_orm_macros::table;

#[table(name = "pipeline_runs")]
#[index("idx_runs_pipeline", pipeline_id)]
#[unique_index("uq_runs_external_id", external_id)]
pub struct PipelineRun {
  #[column(primary_key, not_null)]
  pub id: Uuid,
  #[column(not_null, references = "pipelines(id)", on_delete = "cascade")]
  pub pipeline_id: Uuid,
  #[column(not_null)]
  pub external_id: Text,
  #[column(not_null, default = "'pending'")]
  pub status: Text,
  #[column(not_null, default = "unixepoch()")]
  pub created_at: Integer,
  pub finished_at: Integer,
  pub attempts: Integer,
}
```

The struct itself keeps its fields (the marker types are stripped of their
`#[column]` attributes); everything else is generated next to it.

## What the macro generates

| Item | Shape |
|---|---|
| `PipelineRun::table_def()` | `TableDef` with columns, indexes, primary key, strictness and table-kind metadata, through the `TableSchema` trait. |
| `mod pipeline_runs` | Named after the **table**, holds `TABLE`, `ALL_COLUMNS` and one `Column<T>` per field. |
| `PipelineRun::select()` | `SelectBuilder` bound to the table, no column list. |
| `PipelineRun::select_for::<T>()` | `SelectBuilder` with `columns_raw(T::REQUIRED_COLUMNS)`. |
| `PipelineRun::insert()` / `update()` / `delete()` | The matching builders, bound to the table. |

```rust
pipeline_runs::TABLE;        // "pipeline_runs"
pipeline_runs::ALL_COLUMNS;  // ["id", "pipeline_id", "external_id", …]
pipeline_runs::status;       // Column<Text>
```

## Table attributes

| Attribute | Effect |
|---|---|
| `#[table(name = "…")]` | The SQL table name. Required — use a Rust identifier such as `pipeline_runs`, because it also names the generated column module. |
| `#[table(name = "…", strict = true)]` | Emits a SQLite `STRICT` table using the ORM's Turso extension type names. Check engine support for those types; Postgres ignores this flag. See [Column types](column-types.md). |
| `#[primary_key(col_a, col_b)]` | Table-level composite primary key. Cannot be combined with `#[column(primary_key)]`. |
| `#[index("name", col_a, col_b)]` | Secondary index. Repeatable. Use `desc(col)` for a descending column. |
| `#[unique_index("name", col)]` | Unique index. Repeatable — this is how you express multi-column uniqueness. `desc(col)` works the same way. |
| `#[index("name", col, where = "deleted_at IS NULL")]` | Partial index with a raw SQL predicate. Also supported on `#[unique_index(...)]`. |
| `#[view(Name, pick(a, b))]` / `#[view(Name, omit(c))]` | Generates a subset struct from the table. See [Enums and views](enums-views.md). |

## Column attributes

| Attribute | Effect |
|---|---|
| `#[column(primary_key)]` | `PRIMARY KEY`. |
| `#[column(primary_key, autoincrement)]` | Requires `Integer`. Emits `INTEGER PRIMARY KEY AUTOINCREMENT` on SQLite or `INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` on Postgres. |
| `#[column(not_null)]` | Explicit `NOT NULL`. Database primary-key rules can also constrain nullability. |
| `#[column(unique)]` | `UNIQUE` on the column itself. |
| `#[column(default = "…")]` | SQL expression wrapped in `DEFAULT (…)`. Postgres translates `unixepoch()` and `uuid4_str()`; SQLite translates `true`/`false` to `1`/`0`. Other expressions pass through. |
| `#[column(references = "table(col)")]` | Foreign key. |
| `#[column(on_delete = "…")]` / `#[column(on_update = "…")]` | Referential action: `cascade`, `set_null`, `set_default`, `restrict`, `no_action`. |
| `#[column(as_text)]` | Store the field's type as `TEXT` — used for enums and custom types. |
| `#[column(column_type = "Jsonb")]` | Override the inferred `ColumnType` for that field. |
| `#[column(check = "quality BETWEEN 1 AND 5")]` | Raw CHECK body, wrapped in `CHECK (…)`. Overrides an enum's generated CHECK. Cannot be combined with `as_text`. |

Attributes combine in one `#[column(...)]`:

```rust
#[column(not_null, unique, references = "orgs(id)", on_delete = "cascade")]
pub org_id: Uuid,
```

Use `#[column(not_null)]` on the fields of a composite primary key when you need
portable non-null keys. `#[primary_key(...)]` records the column names without
changing their individual `not_null` flags.

Defaults must be valid for the chosen engine. In particular, `uuid4_str()` is
not a built-in function in stock SQLite, and `datetime('now')` is not translated
for Postgres. Use `unixepoch()` with `Integer` for the portable epoch form shown
above.

## Virtual tables

`#[fts5_table]` and `#[vec0_table]` generate the same table metadata, companion
columns and builder factories for SQLite virtual tables:

```rust
use toolu_orm_core::column::{Integer, Text, Vector};
use toolu_orm_macros::{fts5_table, vec0_table};

#[fts5_table(name = "documents_fts", tokenize = "unicode61")]
pub struct DocumentsFts {
  #[column(unindexed)]
  pub document_id: Text,
  pub body: Text,
}

#[vec0_table(name = "document_vectors")]
pub struct DocumentVectors {
  #[column(primary_key)]
  pub id: Integer,
  #[column(dim = 384, distance_metric = "cosine")]
  pub embedding: Vector,
}
```

FTS5 accepts `tokenize`, `prefix`, `content`, `content_rowid`, `columnsize`,
`detail` and `sync_content` options. All columns are stored as text; use `Text`
markers, optionally `unindexed`. Primary keys, `not_null`, `unique`, defaults,
references and indexes are rejected. For external-content tables, opt into
generated synchronization triggers with `sync_content = true` alongside
`content` and `content_rowid`; declaring `content` alone does not create them.

vec0 requires `dim` on each `Vector` field. It also accepts vector `element`
(`"float"`, `"int8"`, `"bit"`) and `distance_metric` (`"l2"`, `"cosine"`,
`"l1"`), plus scalar `partition_key` and `auxiliary` roles. Bit vectors use
their default distance and reject an explicit metric. Load/register
`sqlite-vec` before creating or querying these tables. Both macros reject
secondary indexes; Postgres migration rendering emits an unsupported-dialect
comment for virtual-table creation.

## Registering tables

A `SchemaRegistry` is the input to migration generation. It sorts tables by name,
so the generated SQL is stable across runs.

```rust
use toolu_orm_core::schema::SchemaRegistry;
use toolu_orm_core::table::TableSchema;

let registry = SchemaRegistry::from_tables(vec![
  OrgsTable::table_def(),
  UsersTable::table_def(),
  PipelineRun::table_def(),
]);

registry.find_table("users");  // Option<&TableDef>
registry.tables();             // &[TableDef]
```

Everything downstream — the diff, the migration file, the snapshot — reads this
registry. A table missing from it is a table the generator will try to drop.
